<objective>
Create the cache layer primitives that underpin incremental indexing: ContentHasher (SHA256 via CryptoKit), IndexManifest (global version invalidation), and CacheStore (per-file Scip_Document protobuf persistence). These are pure data/utility types with well-defined inputs and outputs — ideal TDD candidates. Plan 03-02 integrates them into the pipeline.

Purpose: The cache layer introduces persistent state for the first time in scip-swift. These three types form the foundation: ContentHasher detects per-file content changes (INCR-04), IndexManifest triggers global invalidation on toolchain/converter/indexstore-db version changes (INCR-06), and CacheStore serializes/deserializes Scip_Document protobufs keyed by content hash (INCR-03). Building them in isolation with TDD ensures correctness before integration complexity is added.

Output: Three new source files under Sources/scip-swift/Caching/, three test files, all passing.
</objective>

| Boundary | Description |
|----------|-------------|
| disk→CacheStore | Cache files on disk are read into memory as Scip_Document protobufs — corrupted or tampered files could cause deserialization failures |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | Cached .scipdoc files on disk | low | accept | Filenames are SHA256 hashes of source content — injecting a malicious file requires matching a 256-bit hash (computationally infeasible). Deserialization failures are caught by try? and fall back to uncached behavior. |
| T-03-02 | Information Disclosure | Cache directory contents | low | accept | Cache stores only version strings, content hashes, and SCIP protobufs (symbol names/locations). No source code content, no secrets. The .gitignore advisory (added in Plan 03-02) prevents accidental commits. |
| T-03-SC | Tampering | Package installs | N/A | accept | This plan installs zero external packages — CryptoKit is a macOS system framework. No package legitimacy risk. |
</threat_model>
