| Repo source → parser + trivia walk | Untrusted user-repo Swift source crosses into the in-process SwiftSyntax parse; extracted doc text flows verbatim into a protobuf field |
| Cache dir → process | Cached protobuf documents (now carrying documentation) are re-served without re-parsing |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | DoS | Doc walk over untrusted source inside refiner init | low | mitigate | Linear walk over the already-parsed tree in the same init — no second parse, no regex backtracking (research D1); SwiftSyntax is memory-safe and Parser.parse never throws; unreadable files already yield a nil refiner |
| T-09-02 | Information Disclosure | Doc text flows verbatim into SymbolInformation.documentation | low | accept | Verbatim passthrough IS the requirement (DOCS-01 — consumers render); sanitization is out of scope per REQUIREMENTS.md; no eval, no path derivation, nothing beyond the file's own comments leaves the machine (research V5) |
| T-09-03 | Tampering | Stale doc-less caches served under an unchanged cache version | low | accept | Cache entries are content-hash keyed; only pre-phase caches lack documentation and any content change re-keys them (self-heal, research D5b); version deliberately not bumped because 0.3.0 is unreleased (Phase 8 D4 precedent) |
| T-09-04 | Tampering | Supply chain via new packages | low | accept | No package installs this phase — swift-syntax 602.0.0 was exact-pinned and legitimacy-audited in Phase 8; no dependency file changes |
