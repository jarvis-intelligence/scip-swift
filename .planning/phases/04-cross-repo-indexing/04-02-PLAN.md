    Write the new unit tests first (RED), then expand ScipIndexMerger to pass them (GREEN).

    Modify ScipIndexMerger.merge to accept an additional `repoIdentifiers: [String]` parameter (parallel array to indexes — each entry is the path-prefix for that index's documents). The merge algorithm becomes:

    1. Metadata: same as Plan 01 — use first index's tool info, override projectRoot.
    2. Documents: iterate indexes with their corresponding repoIdentifier. For each document in each index, set document.relativePath = "\(repoIdentifier)/\(originalRelativePath)" then append to merged.documents. This prevents duplicateDocumentWarning when two repos have the same source tree structure (RESEARCH Pitfall 3).
    3. Build definedSymbol set: iterate all merged.documents, collect every doc.symbols.symbol into a Set<String>.
    4. External symbols: iterate all indexes. For each external symbol, include it in the merged output only if: (a) it is NOT in definedSymbol (prevents bothLocalAndExternalSymbolError per RESEARCH Pitfall 2), AND (b) it has not already been added (deduplication via dictionary keyed by symbol string — prevents duplicateSymbolInfoWarning). This preserves relationship targets because symbols not defined in any document are kept (RESEARCH Pitfall 4 — only strip confirmed-defined symbols, never strip merely because they appear in multiple external lists).
    5. Sort merged.externalSymbols by symbol string.
    6. Return merged index.

    Update IndexManyCommand.run() to build the repoIdentifiers array from each repo path's last path component (URL(fileURLWithPath:).lastPathComponent) and pass it to ScipIndexMerger.merge. The merge signature changes from merge(_:projectRoot:) to merge(_:repoIdentifiers:projectRoot:).

    The merge function must handle the edge case where indexes and repoIdentifiers have mismatched counts by using zip(indexes, repoIdentifiers) — if repoIdentifiers is shorter, documents get unprefixed paths; if longer, the extra identifiers are ignored.
  </action>
