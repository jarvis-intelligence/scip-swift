  <action>
    Create .github/workflows/release.yml following the exact workflow structure from 02-RESEARCH.md "DIST-03: Release Workflow" code example.

    Workflow configuration:
    - `name: Release`
    - Trigger: `on: push: tags: ['v*']`
    - Single job `release` on `runs-on: macos-26` (arm64 GA runner per research — cross-compile covers both architectures)
    - `permissions: contents: write` (for gh release create)

    Steps in order (all sequential — SHA256 must be computed before formula update):
    1. `actions/checkout@v5`
    2. Select Xcode: `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`
    3. Build arm64: `swift build -c release --triple arm64-apple-macosx14 --scratch-path .build/arm64`
    4. Build x86_64: `swift build -c release --triple x86_64-apple-macosx14 --scratch-path .build/x86`
    5. Create universal binary: `lipo -create` the two arch binaries from their respective scratch-path output dirs into `scip-swift`, then verify with `lipo -info scip-swift` and `./scip-swift --version`
    6. Create tarball + compute SHA256: `tar czf scip-swift-{VERSION}.tar.gz scip-swift`, then `shasum -a 256`, output tarball/sha256/version via $GITHUB_OUTPUT
    7. Create GitHub Release: `gh release create "${GITHUB_REF_NAME}" "{tarball}" --title "${GITHUB_REF_NAME}" --generate-notes` using GH_TOKEN from secrets.GITHUB_TOKEN
    8. Update tap formula: clone the tap repo using `HOMEBREW_TAP_TOKEN` secret (`git clone "https://x-access-token:${HOMEBREW_TAP_TOKEN}@github.com/{TAP_OWNER}/homebrew-scip-swift.git"`), then use `sed -i ''` (BSD sed on macOS runner) to replace the url, sha256, and version lines in Formula/scip-swift.rb, then `git add`, `git commit -m "scip-swift {VERSION}"`, `git push origin main`

    Use `{TAP_OWNER}` replaced with the owner confirmed in Task 1 for all URLs. Use `macosx14` (not bare `macosx`) in the --triple flags to target macOS 14 as minimum deployment target, matching Package.swift .macOS(.v14) — per research Pitfall 2 (bare macosx uses SDK default which may be macOS 26, excluding macOS 14/15 users).

    Do NOT use `--arch arm64 --arch x86_64` (switches to xcode build system, different output paths). Do NOT use `--static-swift-stdlib` (dynamic Swift runtime is correct for macOS 14+, per research Pitfall 4). Do NOT use macos-13 (deprecated/removed) or macos-14 (deprecated) runner labels.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions → GitHub Releases | CI publishes tarball to public Releases (trust: PAT-scoped, SHA256-verifiable) |
| GitHub Actions → tap repo | CI pushes formula update cross-repo via PAT (trust: PAT with repo scope) |
| GitHub Releases → Homebrew user | User downloads tarball, Homebrew verifies SHA256 before install |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-03 | Tampering | Release tarball in transit | high | mitigate | SHA256 verification in formula — Homebrew enforces checksum match before install; computed in CI after build, written to formula before user sees it |
| T-02-04 | Information Disclosure | HOMEBREW_TAP_TOKEN in CI logs | high | mitigate | Token accessed only via `${{ secrets.HOMEBREW_TAP_TOKEN }}` expression syntax (GitHub masks secrets in logs); never echoed or assigned to a visible variable |
| T-02-05 | Spoofing | Malicious tap injection | medium | accept | Users must explicitly run `brew tap {owner}/scip-swift` — Homebrew's tap trust model requires user confirmation on first use |
| T-02-SC | Tampering | No package-manager installs in this phase | low | accept | No npm/pip/cargo packages involved — formula is Ruby DSL executed by Homebrew, workflow uses pre-installed runner tools (swift, lipo, gh, shasum, sed, git) |
</threat_model>
